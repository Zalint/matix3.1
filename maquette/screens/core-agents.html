Règles du registre

Core §7.2 · §10.2 · Technique §10 · Finance §9.3
  • À la demande uniquement. Chaque agent est interrogé uniquement à la demande explicite d'un utilisateur ; aucun écran ne déclenche d'appel automatique en arrière-plan (chargement de dashboard, rafraîchissement de KPI).
  • Droits effectifs = droits de l'agent ∩ droits du profil utilisateur. Les règles de sensibilité, validation et audit restent applicables ; Hautement sensible : restrictions possibles pour les agents IA (§5.3).
  • Budget mensuel plafond. Au-delà du plafond, l'agent cesse de répondre jusqu'au mois suivant ou jusqu'à relèvement explicite par un utilisateur autorisé.
  • Override temporaire. Un modèle plus coûteux peut être choisi pour une requête ou une période limitée ; l'override est audité, expire automatiquement et revient au routage par défaut ; le plafond reste applicable sauf relèvement explicite.
  • Sobriété V1. Aucun agent n'exploite de base vectorielle dédiée, ni d'indexation sémantique globale, ni de conservation massive des conversations pour créer une mémoire implicite ; seules les traces nécessaires à l'audit et les données explicitement utiles sont conservées (Technique §10).
  • Principe : si une règle déterministe suffit, ne pas utiliser l'IA. Le routage privilégie par défaut le modèle répondant au besoin au coût le plus faible.
  • Écriture encadrée. Un agent ayant des droits d'écriture doit passer en Test/Recette avant Production ; le Conseiller financier ne modifie pas directement les écritures financières et ne dispose pas d'une console SQL utilisateur (Finance §9.3).
Compromis assumé (Technique §10) : sans base vectorielle ni indexation sémantique, un agent ne peut pas retrouver rapidement des situations passées similaires par recherche floue ; il raisonne sur les données structurées interrogées à la demande. Acceptable au volume actuel ; à revisiter explicitement, agent par agent, si l'usage évolue.

Relever temporairement le modèle

Un utilisateur autorisé peut choisir temporairement, pour une requête ou une période limitée, un modèle plus coûteux pour un agent donné ; le système revient ensuite automatiquement au modèle par défaut, et le plafond budgétaire reste applicable sauf relèvement explicite (§7.2).
Par défaut, le routage choisit le modèle répondant au besoin au coût le plus faible (Technique §10) · le retour anticipé au modèle par défaut se fait par « Révoquer » sur la carte de l'agent

Comment ça marche : Agents IA

Ce registre centralise tous les agents IA de l'ERP : les profils autorisés (permission core.agents.budget / core.agents.override) y fixent le budget de chaque agent, activent un agent inactif ou relèvent temporairement son modèle ; les autres profils le consultent en lecture.
  • Deux catégories d'agents. Conseiller (consulte, recommande, jamais d'écriture directe) et Exécutant (uniquement les actions explicitement autorisées) : le registre compte 2 Conseillers et 1 Exécutant sur 3 agents (§7.2).
  • Interrogation à la demande uniquement. Aucun agent n'est appelé automatiquement par un écran (dashboard, rafraîchissement de KPI) : le compteur « Requêtes déclenchées par un écran » reste à 0 (§7.2).
  • Budget mensuel plafond. Au-delà de son plafond, un agent cesse de répondre jusqu'au mois suivant ou jusqu'à relèvement explicite. AG-01 a consommé sur en août, soit 62 % (§7.2).
  • Droits effectifs = droits de l'agent ∩ droits du profil utilisateur. La ligne « Droits effectifs pour vous » de chaque carte recalcule ce croisement pour le profil actif ; sensibilité, validation et audit restent applicables (§10.2).
  • Override temporaire de modèle. Un utilisateur autorisé force un modèle plus coûteux pour une requête ou une durée limitée ; le retour au modèle par défaut est automatique. 1 override est actif : AG-01, modèle avancé, jusqu'au 27/08 · 18:00 (Technique §10).
  • Écriture encadrée. Un agent aux droits d'écriture passe en Test/Recette avant Production, ne modifie pas directement les écritures financières et n'a pas de console SQL utilisateur : AG-02 est en statut Test / Recette (Finance §9.3).
Refus par défaut : « Nouvel agent », le champ budget et le bouton d'override restent visibles mais désactivés avec leur motif si le profil actif n'a pas la permission requise — jamais masqués sans explication.
